# Seed Data Pipeline (`data/`) — Feature M6

This folder holds the reproducible seed data of the CSE305 Library Management System:
**real book metadata from Open Library** plus **100% synthetic operational data**
(members, librarians, copies, loans, fines, reservations).

> [!IMPORTANT]
> **All personal data in this project is synthetic.** Member names, member IDs, e-mail
> addresses, and librarian accounts are fictional and generated by a script. They are
> **not related to any real Adnan Menderes University (ADU) student, academic staff
> member, or librarian**, and they are not related to any real person. Any resemblance
> of a generated name to a real person is purely accidental. E-mail addresses use the
> reserved, non-routable domain `synthetic.lms.local`. No national IDs, phone numbers,
> or real student numbers exist anywhere in the repository. No passwords or credentials
> are generated or stored (authentication seeding will be designed in a later story).

## 1. File header exception

JSON cannot hold comments, so the generated files in `data/seed/*.json` carry **no** mandatory
file header. This is a documented exception in `AGENTS.md` section 2 ("Generated JSON Data
Files Exception"). Authorship is stated here (Ibrahim Temur, Omer Faruk Kuş, student numbers
`231805033`, `231805026`); every script in `tools/data/` and every Markdown file keeps the header.

## 3. How to regenerate (PowerShell, from the repository root)

```powershell
# 1. One-time setup: virtual environment (gitignored) and pinned dependencies
python -m venv tools\data\.venv
tools\data\.venv\Scripts\python.exe -m pip install -r tools\data\requirements.txt

# 2. Fetch real book metadata from Open Library (needs internet; ~35 requests, >= 1.2 s apart).
#    Open Library asks for a contact e-mail in the User-Agent. It is read from an environment
#    variable for this PowerShell session only and is never written to the repository.
$env:LMS_CONTACT_EMAIL = "<your e-mail>"
tools\data\.venv\Scripts\python.exe tools\data\fetch_books.py

# 2b. Re-run without any network access (uses data\raw\openlibrary cache; no e-mail needed)
tools\data\.venv\Scripts\python.exe tools\data\fetch_books.py --offline

# 3. Generate the synthetic data (offline, deterministic; reads only books-openlibrary.json)
tools\data\.venv\Scripts\python.exe tools\data\generate_synthetic.py

# 4. Run the validation tests
tools\data\.venv\Scripts\python.exe -m unittest discover -s tools\data\tests -v
```

`fetch_books.py` stops with an error if `LMS_CONTACT_EMAIL` is missing and a network request is needed.
Use `--refresh` to ignore the cache and fetch again.

**Reproducibility.**

* `generate_synthetic.py` is a pure function of `books-openlibrary.json`: fixed random seed
  (`RANDOM_SEED = 20261022`), fixed reference date, and pinned Faker version (`tr_TR` locale).
  Re-running it produces byte-identical files (verified by `ReproducibilityTests`). It was developed
  and tested with Python 3.11; a different Python or Faker version may change the generated names or
  random choices.
* `books-openlibrary.json` is a **snapshot** of a live service. Open Library results change over time,
  so a fresh online run can yield a different book list. The committed snapshot is the reference;
  with the raw cache present, the fetch step is repeatable offline as well.

## 4. Sources, license, and terms

### Open Library (real bibliographic metadata)

* Source: Open Library Search API, `https://openlibrary.org/search.json`
  (documentation: <https://openlibrary.org/dev/docs/api/search>), accessed on 2026-10-22.
* **Data license:** the Open Library FAQ states that its catalog was created from data that
  libraries *dedicated into the public domain*, and that contributions are given under the
  **Creative Commons CC0 1.0 Universal** license
  (<https://openlibrary.org/help/faq/using>, section "Who owns the Open Library catalog?").
  We therefore treat the bibliographic metadata as public-domain/CC0 data; attribution to Open Library
  is given here as good practice.
* **API terms and usage guidelines:** <https://openlibrary.org/developers/api>. Requests should be
  cached, identified with a descriptive `User-Agent` including a contact, kept at the default limit of
  1 request per second, and must not scrape HTML or bulk-harvest the API (bulk access: monthly data dumps,
  <https://openlibrary.org/developers/dumps>). This project follows those rules: about 35 requests in total
  (hard cap 80), at least 1.2 seconds apart, raw responses cached in `data/raw/`, JSON endpoints only.
* **Cover images** are **not** downloaded or stored. Only the numeric `coverId` and the URL pattern
  `https://covers.openlibrary.org/b/id/<coverId>-M.jpg` are kept so that the application can link to them.
  Open Library is an initiative of the Internet Archive; for reuse of images see the Internet Archive terms
  (<https://archive.org/about/terms.php>).
* The `User-Agent` sent is `CSE305-ADU-LibraryManagementSystem/1.0 (student course project, Adnan Menderes
  University; contact: <e-mail from LMS_CONTACT_EMAIL>)`.

### Synthetic data

Generated locally with the [Faker](https://faker.readthedocs.io/) library (`tr_TR` locale) for fictional
Turkish-style names and with Python's `random` module (fixed seed). No external data source is involved.

## 5. Assumptions used (`docs/01-proposal/PROJECT_PROPOSAL.md`, section 5)

These are project assumptions, **not** official ADU library regulations.

| ID | Rule applied by the data and verified by the tests |
|---|---|
| ASSUMPTION-02 | `STUDENT`: at most 3 active loans; `ACADEMIC_STAFF`: at most 5 (checked at every checkout, not only today) |
| ASSUMPTION-03 | Loan period: `STUDENT` 14 days; `ACADEMIC_STAFF` 30 days |
| ASSUMPTION-04 | At most 1 renewal for one more standard period, only before the loan is overdue; active loans on titles with a hold queue are never renewed |
| ASSUMPTION-05 | Fine: 5.00 TRY per overdue calendar day, capped at 250.00 TRY per loan (cap reached at 50 days) |
| ASSUMPTION-06 | No member borrows while having an overdue loan or an unpaid fine (checked point-in-time at every checkout); `SUSPENDED` members hold no active loans |
| ASSUMPTION-07 | Reservations are per title, FIFO; a returned copy becomes `RESERVED` for the head of the queue |
| ASSUMPTION-08 | 100% synthetic identities; no real ADU identifiers |
| ASSUMPTION-09 | 1 to 4 physical copies per title, barcodes `LMS-COPY-1001`, `LMS-COPY-1002`, ... |

Additional seed-data conventions (not policy): *due soon* means due within 0 to 3 days; a loan that is due
today is **not** overdue; overdue days = (return date or reference date) - due date; there is no grace period.

> [!NOTE]
> **Reference date.** All seed dates are relative to `REFERENCE_DATE = 2026-10-22`
> (`tools/data/lms_seed_common.py`), not to the day the application is started. As real time passes, "overdue"
> and "due soon" loans in the seed data become stale. The seed loader story should evaluate **shifting all
> seed dates relative to the application start date** (also tracked as an open item in
> `docs/process/PROJECT_STATE.md`).

## 6. File formats

All files are UTF-8 (no BOM), LF line endings, a JSON array of objects. Dates are ISO-8601 `YYYY-MM-DD`.
`null` means "not applicable". Natural keys are used for references (no database IDs).

### `books-openlibrary.json`

| Field | Description |
|---|---|
| `isbn13` | Unique, valid ISBN-13 (a valid ISBN-10 is converted; otherwise the record is skipped) |
| `title`, `subtitle` | Title; subtitle or `null` |
| `authors` | 1 to 5 author names |
| `publisher` | Publisher of the selected edition |
| `firstPublishYear` | First publication year of the work |
| `category` | One of 11 categories: Computer Science, Software Engineering, Programming, Databases, Mathematics, Physics & Natural Sciences, Engineering, Fiction, History, Philosophy & Social Sciences, Turkish Literature |
| `subjects` | Up to 5 raw Open Library subjects |
| `pageCount` | **Work-level median** page count (Open Library `number_of_pages_median`). It is the median over all editions of the work and **may not match the page count of the specific edition identified by `isbn13`** |
| `coverId`, `coverUrl` | Open Library cover id and derived URL (image not stored) |
| `openLibraryWorkKey` | Open Library work key (one record per work) |

The `isbn13`, `publisher`, `subtitle`, and cover come from one matching edition of the work; `title`,
`authors`, `firstPublishYear`, `subjects`, and `pageCount` are work-level values. Incomplete records are
dropped (no ISBN-13, publisher, author, year, page count, or cover). The `category` is the query's default
category, refined by ordered subject keyword rules for technical queries only (see `fetch_books.py`).
Records are deduplicated by ISBN-13 and by work key.

### `members.json` (60 rows)

`memberId` (`SYN-STU-0001`.. or `SYN-STF-0001`..), `firstName`, `lastName`, `email`
(`syn-stu-0001@synthetic.lms.local`), `memberType` (`STUDENT` | `ACADEMIC_STAFF`),
`status` (`ACTIVE` | `SUSPENDED`), `department` (generic fictional label), `registeredOn`.

### `librarians.json` (3 rows)

`username` (`syn-lib-0001`..), `displayName`, `email`, `role` (`ROLE_LIBRARIAN`). **No password or credential field.**

### `copies.json`

`barcode` (unique, `LMS-COPY-1001`..), `isbn13` (FK to books), `status`
(`AVAILABLE` | `LOANED` | `RESERVED` | `MAINTENANCE` | `LOST`).
`LOANED` copies are exactly the copies with an `ACTIVE` loan; `RESERVED` copies are exactly the copies held by a `READY` reservation.

### `loans.json`

`loanId` (`LOAN-0001`..), `memberId` (FK), `copyBarcode` (FK), `checkoutDate`, `dueDate`
(checkout + period x (1 + `renewalCount`)), `returnDate` (`null` while active), `status`
(`ACTIVE` | `RETURNED`), `renewalCount` (0 or 1), `renewedOn` (`null` if never renewed).

### `fines.json`

`fineId` (`FINE-0001`..), `loanId` (FK, at most one fine per loan), `memberId` (FK), `overdueDays`,
`amount` (**decimal string** with two digits, e.g. `"125.00"`, to preserve scale for `BigDecimal`), `currency` (`TRY`),
`status` (`PAID` | `WAIVED` | `UNPAID`), `assessedOn` (return date for returned loans; the reference date for
active overdue loans, whose fine is still accruing), `settledOn`, `settledBy` (librarian `username`, FK; `null` if unpaid).

### `reservations.json`

`reservationId` (`RES-0001`..), `isbn13` (FK), `memberId` (FK), `queuePosition` (1..n, FIFO by `createdOn`),
`status` (`WAITING` | `READY`), `createdOn`, `readyCopyBarcode` (the `RESERVED` copy for a `READY` reservation, otherwise `null`).
Queues exist only on titles with no `AVAILABLE` copy: most titles have all copies `LOANED`; a few have one
`RESERVED` copy waiting for pickup by the member at position 1.

## 7. Validation

`tools/data/tests/` contains Python `unittest` suites (no network access): ISBN conversion/checksum helpers,
Open Library record normalization, fine formula and cap, and the validation of the committed seed files
(row counts, unique ISBN-13 and barcodes, ISBN checksums, valid dates, foreign keys, loan limits, double-loan
prevention, borrowing-block rule, fine amounts and statuses, FIFO queues, absence of credentials and real
e-mail addresses, and byte-identical regeneration).
