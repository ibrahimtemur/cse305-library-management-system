# Seed Data Pipeline (`data/`) — Feature M6

This folder holds the reproducible seed data of the CSE305 Library Management System:
**real book metadata from Open Library** plus **100% synthetic operational data**
(members, librarians, copies, loans, fines, reservations).

> [!IMPORTANT]
> **All personal data in this project is synthetic.** Member names, member IDs, e-mail
> addresses, and librarian accounts are fictional and generated by a script. They are
> **not related to any real Adnan Menderes University (ADU) student, academic staff
> member, administrative staff member, or librarian**, and they are not related to any
> real person. Any resemblance of a generated name to a real person is purely accidental.
> E-mail addresses use the reserved, non-routable domain `synthetic.lms.local`. No national
> IDs, phone numbers, or real student numbers exist anywhere in the repository. No passwords,
> credentials, or book price appraisals are generated or stored in the seed files.

## 1. File header exception

JSON cannot hold comments, so the generated files in `data/seed/*.json` carry **no** mandatory
file header. This is a documented exception in `AGENTS.md` section 2 ("Generated JSON Data
Files Exception"). Authorship is stated here (Ibrahim Temur, Omer Faruk Kuş, student numbers
`231805033`, `231805026`); every script in `tools/data/` and every Markdown file keeps the header.

## 3. How to regenerate (PowerShell, from the repository root)

```powershell
# 1. One-time setup: virtual environment (gitignored) and pinned dependencies
python -m venv tools\data\.venv
tools\data\.venv\Scripts\python.exe -m pip install -r tools\data\requirements.txt

# 2. Fetch real book metadata from Open Library (needs internet; ~35 requests, >= 1.2 s apart).
#    Open Library asks for a contact e-mail in the User-Agent. It is read from an environment
#    variable for this PowerShell session only and is never written to the repository.
$env:LMS_CONTACT_EMAIL = "<your e-mail>"
tools\data\.venv\Scripts\python.exe tools\data\fetch_books.py

# 2b. Re-run without any network access (uses data\raw\openlibrary cache; no e-mail needed)
tools\data\.venv\Scripts\python.exe tools\data\fetch_books.py --offline

# 3. Generate the synthetic data (offline, deterministic; reads only books-openlibrary.json)
tools\data\.venv\Scripts\python.exe tools\data\generate_synthetic.py

# 4. Run the validation tests
tools\data\.venv\Scripts\python.exe -m unittest discover -s tools\data\tests -v
```

`fetch_books.py` stops with an error if `LMS_CONTACT_EMAIL` is missing and a network request is needed.
Use `--refresh` to ignore the cache and fetch again.

**Reproducibility.**

* `generate_synthetic.py` is a pure function of `books-openlibrary.json`: fixed random seed
  (`RANDOM_SEED = 20261022`), fixed reference date (`REFERENCE_DATE = 2026-10-22`), and pinned
  Faker version (`tr_TR` locale). Re-running it produces byte-identical files (verified by
  `ReproducibilityTests`). It was developed and tested with Python 3.11; a different Python or
  Faker version may change the generated names or random choices.
* `books-openlibrary.json` is a **snapshot** of a live service. Open Library results change over time,
  so a fresh online run can yield a different book list. The committed snapshot is the reference;
  with the raw cache present, `fetch_books.py --offline` is 100% repeatable offline with zero network requests.

## 4. Sources, license, and terms

### Open Library (real bibliographic metadata)

* Source: Open Library Search API, `https://openlibrary.org/search.json`
  (documentation: <https://openlibrary.org/dev/docs/api/search>), accessed on 2026-10-22.
* **Data license:** the Open Library FAQ states that its catalog was created from data that
  libraries *dedicated into the public domain*, and that contributions are given under the
  **Creative Commons CC0 1.0 Universal** license
  (<https://openlibrary.org/help/faq/using>, section "Who owns the Open Library catalog?").
  We therefore treat the bibliographic metadata as public-domain/CC0 data; attribution to Open Library
  is given here as good practice.
* **API terms and usage guidelines:** <https://openlibrary.org/developers/api>. Requests should be
  cached, identified with a descriptive `User-Agent` including a contact, kept at the default limit of
  1 request per second, and must not scrape HTML or bulk-harvest the API (bulk access: monthly data dumps,
  <https://openlibrary.org/developers/dumps>). This project follows those rules: about 35 requests in total
  (hard cap 80), at least 1.2 seconds apart, raw responses cached in `data/raw/`, JSON endpoints only.
* **Cover images** are **not** downloaded or stored. Only the numeric `coverId` and the URL pattern
  `https://covers.openlibrary.org/b/id/<coverId>-M.jpg` are kept so that the application can link to them.
  Open Library is an initiative of the Internet Archive; for reuse of images see the Internet Archive terms
  (<https://archive.org/about/terms.php>).
* The `User-Agent` sent is `CSE305-ADU-LibraryManagementSystem/1.0 (student course project, Adnan Menderes
  University; contact: <e-mail from LMS_CONTACT_EMAIL>)`.

### Synthetic data

Generated locally with the [Faker](https://faker.readthedocs.io/) library (`tr_TR` locale) for fictional
Turkish-style names and with Python's `random` module (fixed seed). No external data source is involved.

## 5. Business rules applied (`docs/02-inception/BUSINESS_RULES.md`)

The seed v2 dataset enforces the confirmed Adnan Menderes University (ADU) library lending regulations
and explicit project assumptions documented in [`docs/02-inception/BUSINESS_RULES.md`](../docs/02-inception/BUSINESS_RULES.md):

| Rule ID | Status | Rule applied by the data and verified by the tests |
|---|---|---|
| `BR-002` | `CONFIRMED` + `ASSUMPTION-17` | Borrowing limits checked point-in-time at every checkout: `ACADEMIC_STAFF` = at most **7** active loans; `ADMINISTRATIVE_STAFF` = at most **3** active loans; `STUDENT` = at most **3** active loans |
| `BR-003` | `CONFIRMED` | Standard loan period: **30 calendar days** for all three member types (`ACADEMIC_STAFF`, `ADMINISTRATIVE_STAFF`, `STUDENT`) |
| `BR-004`, `BR-005` | `CONFIRMED` + `ASSUMPTION-11` | At most **1 renewal** (`+30` days), only before the loan is overdue; loans on titles with a reservation queue are never renewed |
| `BR-006` | `CONFIRMED` + `ASSUMPTION-12` | **Post-renewal 30-day cooldown:** after returning a renewed loan (`renewalCount == 1`), the same member does not borrow the same title (`isbn13`) again within 30 calendar days of `returnDate` (does not restrict reservations) |
| `BR-007`..`BR-010` | `CONFIRMED` + `ASSUMPTION-10` | Overdue fine: **0.25 TRY (25 kuruş)** per overdue calendar day per loan with **no maximum cap** (`amount = 0.25 * overdueDays`, zero grace period) |
| `BR-011` | `CONFIRMED` + `ASSUMPTION-06` | No member borrows while holding an overdue active loan or an `UNPAID` fine (checked point-in-time at every checkout); `SUSPENDED` members hold no active loans |
| `BR-012`, `BR-013` | `CONFIRMED` + `ASSUMPTION-13` | Reservations are per title (`isbn13`), strictly FIFO (`queuePosition = 1..n`) when 0 copies are `AVAILABLE`; a `READY` reservation (`queuePosition == 1`) binds a `RESERVED` copy (`readyCopyBarcode`) with `readyOn` and a **3-day pickup hold window** (`holdUntil = readyOn + 3 days`) |
| `BR-014` | `CONFIRMED` + `ASSUMPTION-14` | Non-circulating reference works (`referenceOnly = true`: dictionaries, encyclopedias, catalogs matched deterministically by word boundary) are never loaned or reserved; all their copies remain `AVAILABLE` |
| `BR-015`, `BR-017` | `CONFIRMED` + `ASSUMPTION-12`/`15` | Each `LOST` physical copy corresponds to a closed loan (`status = "LOST"`, `returnDate = null`) with `lostReportedOn` within the active 30-day replacement window (`REFERENCE_DATE - 30 days < lostReportedOn <= REFERENCE_DATE`), where overdue fine accrual stops at `lostReportedOn`. (`appraisedValue` for unreplaced lost books is a runtime Librarian input only, never stored in seed files.) |
| `BR-018` | `ASSUMPTION-08`/`16`/`17` | 100% synthetic identities (`SYN-STU-*`, `SYN-STF-*`, `SYN-ADM-*`, `syn-lib-*`, `@synthetic.lms.local`) with zero real PII and zero credentials |

Additional seed-data conventions: *due soon* means an active loan due within 0 to 3 days of `REFERENCE_DATE`;
a loan that is due on the evaluation date (`endDate == dueDate`) is **not** overdue.

> [!NOTE]
> **Reference date.** All seed dates are relative to `REFERENCE_DATE = 2026-10-22`
> (`tools/data/lms_seed_common.py`), not to the day the application is started. As real time passes, "overdue",
> "due soon", and "hold until" dates in the seed data become stale. The seed loader story should evaluate **shifting all
> seed dates relative to the application start date** (tracked as `OPEN-04` in
> `docs/process/PROJECT_STATE.md`).

## 6. File formats

All files are UTF-8 (no BOM), LF line endings, a JSON array of objects. Dates are ISO-8601 `YYYY-MM-DD`.
`null` means "not applicable". Natural keys are used for references (no database IDs).

### `books-openlibrary.json` (782 rows)

| Field | Description |
|---|---|
| `isbn13` | Unique, valid ISBN-13 (a valid ISBN-10 is converted; otherwise the record is skipped) |
| `title`, `subtitle` | Title; subtitle or `null` |
| `authors` | 1 to 5 author names |
| `publisher` | Publisher of the selected edition |
| `firstPublishYear` | First publication year of the work |
| `category` | One of 11 categories: Computer Science, Software Engineering, Programming, Databases, Mathematics, Physics & Natural Sciences, Engineering, Fiction, History, Philosophy & Social Sciences, Turkish Literature |
| `subjects` | Up to 5 raw Open Library subjects |
| `pageCount` | **Work-level median** page count (Open Library `number_of_pages_median`). It is the median over all editions of the work and **may not match the page count of the specific edition identified by `isbn13`** |
| `coverId`, `coverUrl` | Open Library cover id and derived URL (image not stored) |
| `openLibraryWorkKey` | Open Library work key (one record per work) |
| `referenceOnly` | Boolean (`true` for 3 non-circulating encyclopedias/dictionaries matched by word-boundary keyword rules: `9780717261680`, `9780824722876`, `9781560917540`; `false` for the remaining 779 circulating books) |

### `members.json` (60 rows: 40 `STUDENT`, 10 `ACADEMIC_STAFF`, 10 `ADMINISTRATIVE_STAFF`)

`memberId` (`SYN-STU-0001`..`0040`, `SYN-STF-0001`..`0010`, or `SYN-ADM-0001`..`0010`), `firstName`, `lastName`, `email`
(`syn-stu-0001@synthetic.lms.local`, `syn-stf-0001@synthetic.lms.local`, `syn-adm-0001@synthetic.lms.local`),
`memberType` (`STUDENT` | `ACADEMIC_STAFF` | `ADMINISTRATIVE_STAFF`),
`status` (`ACTIVE` | `SUSPENDED`), `department` (generic fictional label), `registeredOn`.

### `librarians.json` (3 rows)

`username` (`syn-lib-0001`..`0003`), `displayName`, `email`, `role` (`ROLE_LIBRARIAN`). **No password or credential field.**

### `copies.json` (1,706 rows)

`barcode` (unique, `LMS-COPY-1001`..`LMS-COPY-2706`), `isbn13` (FK to books), `status`
(`AVAILABLE` | `LOANED` | `RESERVED` | `MAINTENANCE` | `LOST`).
`LOANED` copies are exactly the copies with an `ACTIVE` loan; `LOST` copies are exactly the copies with a `LOST` loan;
`RESERVED` copies are exactly the copies held by a `READY` reservation; all copies of `referenceOnly` books are `AVAILABLE`.

### `loans.json` (164 rows)

`loanId` (`LOAN-0001`..`LOAN-0164`), `memberId` (FK), `copyBarcode` (FK), `checkoutDate`, `dueDate`
(`checkoutDate + 30 * (1 + renewalCount)`), `returnDate` (date for `RETURNED` loans; `null` for `ACTIVE` and `LOST` loans),
`lostReportedOn` (date within `(REFERENCE_DATE - 30 days, REFERENCE_DATE]` for `LOST` loans; `null` for `ACTIVE` and `RETURNED` loans),
`status` (`ACTIVE` | `RETURNED` | `LOST`), `renewalCount` (`0` or `1`), `renewedOn` (`null` if never renewed).

### `fines.json` (47 rows)

`fineId` (`FINE-0001`..`FINE-0047`), `loanId` (FK, at most one fine per loan), `memberId` (FK), `overdueDays`,
`amount` (**decimal string** with two digits, `0.25 * overdueDays` with no cap, e.g. `"13.25"`, to preserve scale for `BigDecimal`),
`currency` (`TRY`), `status` (`PAID` | `WAIVED` | `UNPAID`), `assessedOn` (`returnDate` for `RETURNED` loans; `lostReportedOn` for
`LOST` loans whose fine stopped accruing on the petition date; `REFERENCE_DATE` for `ACTIVE` overdue loans), `settledOn`,
`settledBy` (librarian `username`, FK; `null` if unpaid).

### `reservations.json` (22 rows across 12 titles)

`reservationId` (`RES-0001`..`RES-0022`), `isbn13` (FK), `memberId` (FK), `queuePosition` (`1..n`, FIFO by `createdOn`),
`status` (`WAITING` | `READY`), `createdOn`, `readyCopyBarcode` (the `RESERVED` copy for a `READY` reservation, otherwise `null`),
`readyOn` (hold start date for a `READY` reservation, otherwise `null`), `holdUntil` (`readyOn + 3 days` for a `READY` reservation, otherwise `null`).
Queues exist only on circulating titles (`referenceOnly == false`) with no `AVAILABLE` copy.

## 7. Validation

`tools/data/tests/` contains 80 offline Python `unittest` checks: ISBN conversion/checksum helpers,
word-boundary `referenceOnly` detection, Open Library record normalization, uncapped `0.25 TRY/day` fine formula,
and validation of the committed seed files (row counts, unique ISBN-13 and barcodes, ISBN checksums, valid dates,
foreign keys, `7/3/3` loan limits, 30-day loan periods, post-renewal 30-day borrowing cooldown, `LOST` copy fine freeze
within the 30-day replacement window, `READY` reservation 3-day hold window, non-circulating `referenceOnly` invariance,
absence of credentials/appraisedValue/real e-mails, and byte-identical regeneration).
